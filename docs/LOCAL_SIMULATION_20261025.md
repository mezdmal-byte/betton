Дата: 25 октября 2026. Основа — PR #22, `d83d35562917b9fcb2fcdc4076c11499b93f41ac`.
Рабочая ветка — `codex/restore-demo-simulation`. Это локальная тестовая работа, не deployment.

## Что уже существовало и почему было пусто

Сохранены и использованы: `seed_demo_markets.py`, `ux_v3_preview.py`, настоящий Telegram HMAC verifier,
обычные API создания/модерации/ставок, `demo_guarantors.py`, integer reward engine, ledger и settlement.
Новая система автоматических гарантов не создавалась. Расчёт цены, лоты, matching, комиссии и выплаты не менялись.

Прежняя `C:\Users\1\betton\betton-live-test.db` существует: 263 события, в том числе 100 `DEMO[vasily]`,
217 заявок, 73 исполнения, 20 пользователей. Схема без revision marker; большая часть событий уже закрыта.
Текущий прежний Telegram-запуск использовал другую новую базу схемы 4 — с одним событием, без старого DEMO-набора
и без demo actors. В нём `BETTON_DEMO_AUTOMATION=false`. Поэтому старые рынки и шесть автоматических гарантов отсутствовали.

SQLite online backup прежней базы создан до проверки. Поддерживаемая денежная миграция на копии отказала:
у ряда событий сохранённый pot не совпадает с суммой исполнений. Эти строки не исправлялись и не переносились.
Оригинал после работы совпал с исходным SHA-256 побайтно. Отчёты находятся в
`C:\Users\1\betton\.local-preserve\demo-restoration-audit`.

## Два разных режима

### Браузер на компьютере

Двойное нажатие `C:\Users\1\betton\start-betton-simulation.bat` открывает карту
http://127.0.0.1:8877/sandbox/scenarios . Дождитесь `SIMULATION READY`.

На карте есть четыре ссылки: создатель, участник, гарант, модератор. Открывайте их в разных вкладках.
Это существующий loopback sandbox: обычная HMAC-проверка с локальным тестовым токеном;
Host, Origin, client IP и CSP ограничивают его компьютером. Подставные роли не публикуются через туннель.

Данные — отдельная маркированная `betton-test-simulation.sqlite` внутри `.ux-preview/simulation-*`.
Текущий путь указан в `.ux-preview/simulation-runtime/active.json`.

### Настоящий Telegram

Двойное нажатие `C:\Users\1\betton\start-telegram-simulation.bat`, дождаться `TELEGRAM SIM READY`.
В **@SobakaPesBot** открыть персональную кнопку меню **BetTON SIM**. На первой странице выбрать
«Открыть приложение BetTON». Кнопка из ответа на `/start` продолжает вести в прежний обычный запуск.

Этот режим использует отдельную копию только свежего, предварительно маркированного демонстрационного набора,
обычный FastAPI и настоящий токен тестового бота. Ни `/sandbox/session`, ни вход под подставными ролями снаружи
не доступны. Telegram ID пользователя берётся из настоящего подписанного initData. На этом устройстве использованы
уже сохранённые тестовый токен и ID владельца, без вывода секретов.

Меняется только персональная кнопка меню проверенного владельца тестового бота. Глобальное меню,
действующий webhook SobakaPesBot и production webhook betton_p2p_bot остаются прежними.
Новый сервер webhook не принимает и polling не запускает. Сообщения/уведомления в Telegram пользователям не отправляются.
При штатной остановке прежняя персональная кнопка восстанавливается; исходное состояние записано в menu-backup.json.

В Telegram нет переключения подставных ролей. Вы проверяете свой отдельный тестовый аккаунт;
чужие реальные аккаунты и их данные не импортируются. Синтетические поставщики ликвидности и автоматические
гаранты явно помечены «ТЕСТ», у автоматических гарантов `telegram_id=NULL`.

Стартовый баланс обычного нового тестового аккаунта — существующие 1000 TON; для модератора код предусматривает
отдельный тестовый bankroll 1 000 000 TON. Это не настоящие TON и не подключённый кошелёк.

## Доступные сценарии

Новый набор содержит 27 именованных сценариев плюс два исходных sandbox-события — 29 событий при первом запуске.
Номер нужного события смотрите на карте: старые номера из DEMO_QA.md к новой базе не относятся.

| Ключ | Что проверять |
|---|---|
| empty | Нет заявок и сделок, нет выдуманной последней цены или графика |
| yes_only / no_only | Ликвидность только одного исхода |
| book_levels | Три реально исполнимых ценовых уровня, разные объёмы |
| multi_fill | Сохранённое исполнение по трём ценам |
| partial | Частичное исполнение и живой остаток |
| cancel_remainder | Отмена только неисполненного остатка |
| low_liquidity / high_liquidity | Малый и большой банк, разные доступные объёмы |
| full_fill | Полное исполнение двух встречных заявок |
| history | Четыре настоящих исполнения по разным ценам и в разное время |
| closed | Приём остановлен, новые ставки запрещены |
| resolved_yes / resolved_no | Настоящий расчёт соответствующего исхода |
| cancelled | Возврат исполненных ставок и резервов |
| pending | Модерация, отсутствие в публичной ленте |
| private | Обычное частное событие по ссылке |
| legacy_dispute | Старый контракт: реальные ставки → результат → возражение → независимая модерация |
| guarantor_fixed / percent / combined / percent_minimum | Четыре тарифа существующего worker |
| guarantor_negotiator / guarantor_flexible | Уточняющие вопросы и выбор тарифа по условиям |
| decline / no_response / controlled_error | Отказ, отсутствие ответа и безопасная остановка ошибочного сценария |

Новые UX v3 пари имеют собственный контракт окончательного своевременного решения. В них не добавлялось
искусственное окно спора. Для просмотра спора специально создан отдельный legacy-сценарий через прежний API.
Совместимость LMSR отдельно проверяется существующими backend-тестами; его формулы не используются для P2P.

## Что нажимать

### Автоматические гаранты — обновление 2026-10-25

Для **нового** частного события UX v3 с зарегистрированным «ТЕСТ»-гарантом больше не нужна
предварительная настройка. `create_event` регистрирует `DemoGuarantorRun` вместе с событием,
приглашением и idempotency intent в одной транзакции. Повторный запрос возвращает прежнее событие.
Существующие worker, блокировки market/run, курсор прогресса и сервисы переговоров используются без замены.
Старые события автоматически не переоформляются, прошлые действия не повторяются.

| Гарант | Поведение по умолчанию |
|---|---|
| Фикс | 5 TON |
| Процент | 3%; встречное предложение 2% при торге, затем существующая логика принятия |
| Процент + фикс | 3% + 2 TON |
| Процент с минимумом | 3%, минимум 20 TON |
| Переговорщик | Сначала вопрос об источниках/доказательствах; ждёт ответа либо изменения условий; затем 4% |
| Гибкий | 1,5% для простых правил; 2% + 2 TON для правил длиннее 400 символов |

Задержки действий остаются 3–13 секунд плюс интервал worker. Срок приглашения — настоящая минута:
если worker не успел, приглашение истекает штатно. Согласие, подтверждение правил и ставки за пользователя
не выполняются. Для регистрации обязательны test/demo environment, отдельное имя базы, включённая
автоматизация, специальный маркер базы и `DemoGuarantorActor` без Telegram ID. При нарушении этих условий
создание с тестовым актором откатывается целиком. Настоящие гаранты этот путь не используют.

**Рынок и коэффициенты.** Откройте роль участника, найдите «Спутник выйдет на орбиту? · три уровня цены».
Откройте стакан, затем «Свой коэффициент», исход «Да», сумма 60, минимальный коэффициент 1.49.

59.9993 TON со средним коэффициентом около 1.73; остаток около 0.0007 TON можно отменить.
Это следствие реальных целочисленных лотов, не округлённая обещанная полная ставка. Проверьте «Мои ставки».

Откройте событие «Курс закроет день выше порога? · история реальных исполнений» для графика.
У пустого рынка, напротив, должно быть состояние формирования/отсутствия исполненных сделок.
Seeder не назначает последние коэффициенты и не вставляет фиктивные точки графика: источник — P2PFill.

**Своё частное пари с гарантом.** От создателя нажмите «Создать» → «Частное с гарантом», заполните условия,
выберите «ТЕСТ · Фикс» или другую стратегию. После приглашения гарант автоматически ответит в пределах минуты.
Возвращаться на карту или включать сценарий не нужно — регистрация выполняется сервером в транзакции создания.
Примите предложение вознаграждения и подтвердите условия самостоятельно.
Для активного фонда нужны действительные встречные ставки участников. Гарант не ставит на своё пари.

**Результат.** По умолчанию новое пари с тестовым гарантом использует winner_0: после настоящего срока
первый исход с явной пометкой «ТЕСТ: воспроизводимый демонстрационный исход», без проверки реального события.
При недостаточном обеспечении действуют штатные правила возврата. Дополнительные QA-настройки в раскрываемом
разделе карты/Telegram-страницы доступны только тестовому администратору. Они необязательны и меняют будущие
действия: после отклика нельзя превратить историю в «без ответа» или повторно запустить завершённый сценарий.
Пройденные вопросы/торг и финансовая история сохраняются. Режимы winner_0 / winner_1 / cancel ждут настоящего срока окончания. В браузерной проверке
использовался ближайший срок и действительно ожидалось его наступление. Для legacy_dispute откройте событие
от независимого модератора и выполните решение либо возврат. Роли, сроки и финансовые проверки не обходятся.

**Публичное событие и модерация.** Создайте публичное событие. Резервную ссылку можно оставить пустой,
даже если уже введено название резервного источника — незавершённый источник не отправляется.
Отправьте событие, откройте роль модератора → существующую модерацию → одобрите.
«Сохранить и выйти» доступно в мастере, Telegram BackButton возвращает на предыдущий шаг.
После перезагрузки восстанавливается только черновик выбранного пользователя и типа события.

## Остановка, сброс и восстановление

- Браузер: `stop-betton-simulation.bat`; чистое начало: `reset-betton-simulation.bat`.
- Telegram: `stop-telegram-simulation.bat`; чистое начало: `reset-telegram-simulation.bat`.
- Повторный старт не создаёт второй процесс и не повторяет seed. Чужой занятый порт не освобождается принудительно.
- Сброс штатно останавливает соответствующий режим, сохраняет указатель на старое поколение и выбирает новое.
  Старые базы не удаляются и не перезаписываются. Новое поколение получает актуальные сроки из штатного seed.
- При прерывании первого seed повторный запуск откажется принимать частично наполненную базу. Используйте reset,
  который сохранит её и создаст новое поколение. Не удаляйте финансовые строки для «починки».
- Для точного восстановления старого поколения остановите режим, скопируйте нужный previous-*.json обратно в active.json
  его runtime-каталога и запустите снова. Восстановление не обновляет прошедшие сроки: worker применяет реальные дедлайны.

Логи и указатели: `.ux-preview/simulation-runtime/` и `.ux-preview/telegram-simulation-runtime/`.
Токен остаётся в прежнем локальном ignored credentials.env. В Git токена, initData или конфигурации реального пользователя нет.
Cloudflare URL меняется после нового старта; при отсутствии связи запуск завершается с ошибкой без вечного перезапуска.
Штатная остановка Telegram-режима проверена: туннель завершился, прежнее персональное меню восстановилось,
webhook и глобальное меню совпали с исходными.

## Исправления интерфейса

| До | После | Причина |
|---|---|---|
| Один черновик на пользователя для всех типов | Отдельные public/private/guarantor, безопасный импорт старого формата | Частный текст не появляется в публичном событии |
| Название резервного источника без ссылки блокировало шаг | Пустая ссылка оставляет весь резервный источник отсутствующим | Соответствие optional backend-контракту |
| Нельзя явно выйти из середины мастера | «Сохранить и выйти», сохранение текущего черновика | Рабочий выход при скрытой нижней панели |
| Уведомление перекрывало возврат из согласования | Модальный слой выше уведомления; форма временно откладывает popup без mark-read | Нормальные клики и Back доступны |
| Поздний ответ API мог снова открыть уже закрытое согласование | Ответ учитывает текущий экран | Навигация пользователя не отменяется ответом сети |
| Свежая сделка выглядела как «7 часов назад» | Существующий UTC-парсер используется в истории и графике | Naive UTC API больше не интерпретируется как местное время Windows |

«Подробнее» и логика Market Detail не переделывались. Собранный frontend также скопирован в прежнюю локальную
установку с backup старого dist; backend и webhook для этого не перезапускались. Источник исправленного frontend — эта ветка.
