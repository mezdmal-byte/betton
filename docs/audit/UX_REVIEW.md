## Карта сценариев: статический разбор, не прохождение на устройстве

| Шаг | Сценарий | Состояние проверки / рекомендация |
|---|---|---|
| 1 | Вход и онбординг | Компоненты и Telegram auth изучены; реальный host не проверен. Demo использует синтетические роли |
| 2 | Главная → событие | Навигация и источник API изучены; соответствие кадру 22:10070 не проверено |
| 3 | Выбор исхода → быстрое исполнение | Серверная котировка и повтор request_id есть; проверить потерю ответа и возврат на экран |
| 4 | Свой коэффициент → ожидание/частичное исполнение | Остаток отделён от исполнения в модели; текст кнопки отмены должен уточнять остаток |
| 5 | Мои ставки → результат/история | Доказан F1: отсутствуют операции награды гаранта; это функциональная, а не визуальная проблема |
| 6 | Создание трёх типов | Черновик и проверка полей есть; публичные условия длинные; дата вводится как UTC. Повтор создания не идемпотентен |
| 7 | Гарант → приглашение → переговоры | Код содержит минуту на отклик и пять минут согласования; проверить на реальном пользователе достаточность времени. Не менять сроки без продуктового решения |
| 8 | Тариф → согласие → фонд | В GuarantorV3Panel.tsx блок body повторяется внутри чата; вероятна информационная перегрузка. Сначала показать состояние и главное действие, детали свернуть |
| 9 | Результат → отмена/выплата | Окончательное действие использует window.confirm; проверить Telegram Back, повтор на плохой сети и доступность диалога |
| 10 | Модерация → публикация | Сервер разрешает публикацию исправлений без согласия автора; тесты есть. Визуальный маршрут не пройден |
| 11 | Уведомления и профили | Списки и polling изучены. Разделить загрузку/ошибку профиля, проверить переход в частное событие с другого устройства |
| 12 | Admin Center | Только совместимость исходников; интеграция и визуальный аудит отложены по заданию |

Уверенность в наличии ветвей кода высокая; выводы о трудности восприятия — гипотезы средней уверенности до наблюдения пользователей. Наложений, обрезаний, контраста и удобства touch здесь не оценивали.

## Обязательный следующий visual pass

360×800, 390×844, 430×932 и desktop 1440×900; обе темы, RU/EN/ZH, первый/повторный вход. Для каждого шага сохранить текущий screenshot и DOM, состояние/роль/seed/viewport. Проверить длинные заголовки, пустой/односторонний стакан, частичное исполнение, неверный ввод, offline, 401, 403, 409, возврат после отправки, клавиатуру и safe area. Реальный Telegram iOS/Android — отдельный прогон, не подмена браузером.

Приоритет: история денег и ясность удержаний — важное; различение состояний и сохранение форм — важное; плотность переговоров — желательное; косметическая перестройка — необязательное. Внешний вид не изменён.
