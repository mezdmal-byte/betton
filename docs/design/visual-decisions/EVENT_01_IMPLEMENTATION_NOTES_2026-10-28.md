## Перед кодом: сверить существующие контракты

- [ ] Найти действующий механизм расчёта предложения/исполнения и правила сбора. Не выводить формулы из примеров Figma.
- [ ] Проверить поддержку оценки суммы по нескольким уровням, минимального коэффициента, частичного исполнения, ожидающей заявки, её отмены и повторных запросов.
- [ ] Уточнить контракт при изменении доступного объёма/цены между расчётом и отправкой: не вводить самовольно допуск цены и не подменять предложение.
- [ ] Найти источник истории коэффициентов и объёма сделок. Проверить формулу агрегации, единицу объёма и доступную детализацию.
- [ ] Найти действующий чат события; не смешивать его с переговорами создателя и гаранта.

Пути к функциям, endpoints и названия полей намеренно не заданы: в этом задании код не исследован, наличие возможностей не подтверждено.

## Панель ставки: обязательное поведение

- [ ] Выбор исхода подготавливает черновик быстрой ставки в компактной закреплённой панели, без автоматического открытия большого меню способов.
- [ ] До ввода суммы показывать лучший доступный коэффициент; после ввода — предварительный средний для этой суммы по действующей логике.
- [ ] Выбор исхода/переключение режима/сворачивание не размещают ставку и не резервируют деньги.
- [ ] Нормальный путь при достаточном объёме: исход → сумма → видимый расчёт → **«Заключить ставку»** → обработка → результат. Не вставлять дополнительную проверку/подтверждение в обычную быструю ставку.
- [ ] До финального нажатия показать необходимые сумму, коэффициент/расчёт, выплату и сбор без повторяющейся таблицы. Выплата включает первоначальную ставку; не называть её чистой прибылью.
- [ ] Только при нехватке встречного объёма раскрыть текущую исполнимую сумму и ожидающую часть: уменьшить сумму либо задать собственный минимальный коэффициент для ожидающей части.
- [ ] Не создавать «хвост» по произвольной цене и не возвращать его автоматически. Действие с ожидающей частью должно следовать выбору пользователя.
- [ ] Сохранить отдельные сценарии собственного коэффициента и выбора конкретного предложения. Снятие второго подтверждения согласовано для обычной быстрой ставки; автоматически не распространять на остальные сценарии.
- [ ] В конкретном предложении сохранять выбранные исход/коэффициент/лимит. Не подменять другой строкой незаметно.
- [ ] По смене вкладок сохранять черновик. Различать коэффициент в исходах, рассчитанный средний и цену выбранного предложения.
- [ ] При ожидании без исполнения не показывать «Исполнено — 0». При частичном исполнении показывать исполненную и ожидающую суммы.
- [ ] Успех — только по результату сервера. Предотвратить повторную отправку одним/повторными нажатиями и корректно обработать неопределённый результат запроса.

## Жесты, прокрутка, клавиатура

- [ ] Одна панель с компактным и раскрытым положениями; раскрытие вверх/нажатием, сворачивание вниз.
- [ ] При сворачивании сохранять исход, сумму и режим. Сворачивание не является отменой заявки.
- [ ] Учесть конфликт внутренней прокрутки с перетаскиванием; предусмотреть альтернативу жесту. Большую кнопку «Закрыть» из текущего меню способов убрать при переработке.
- [ ] При клавиатуре активное поле и действие доступны, панель не закрывает ввод; при закрытии клавиатуры восстанавливается согласованное состояние.
- [ ] Проверить safe area и высоту Telegram viewport на реальных устройствах; Figma этого не доказывает.

## График

- [ ] Две линии одновременно. Касание одного временного интервала показывает **оба коэффициента**, названия исходов и границы интервала.
- [ ] Объём заключённых ставок за тот же интервал — отдельной мелкой строкой; не подставлять объём вместо второго коэффициента.
- [ ] Переключатель в макете: **1 ч / 24 ч / Всё время**. Одна точка объединяет данные своего интервала, а не весь выбранный период.
- [ ] Коэффициенты агрегировать отдельно по исходам, объём суммировать за тот же интервал. Не удваивать один и тот же объём из-за двух исходов.
- [ ] Точную формулу среднего, шаги интервалов, часовой пояс и интервалы без данных проверить отдельно. Простое/взвешенное по объёму/взвешенное по времени среднее в переписке не выбрано; не выдумывать.
- [ ] Не подменять отсутствие сделок нулевым коэффициентом.

## Обсуждение

- [ ] Компактный блок последних сообщений с вводом внутри блока; можно писать без раскрытия чата.
- [ ] «Открыть чат» раскрывает полное обсуждение; возврат сохраняет контекст события и выбранную ставку.
- [ ] Закреплённая ставка остаётся доступной. С клавиатурой — согласованное компактное отображение; не перекрывать сообщение/отправку.
- [ ] Переносить принятую композицию нативными элементами, не скриншотом PNG.

## Проверки перед приёмкой реализации

- [ ] Обычная быстрая ставка завершается одним финальным нажатием, без второго модального подтверждения.
- [ ] Проверены достаточный/недостаточный объём, несколько уровней, собственный минимум, ожидающая часть и отмена только ожидающей части.
- [ ] Изменение цены/объёма и сетевой сбой не выдают ложный успех и не вызывают скрытое повторное размещение.
- [ ] Состояние сохраняется между четырьмя вкладками, компактной/раскрытой панелью и чатом.
- [ ] Проверены 320/390/430 px, клавиатура, safe area, длинные строки и жесты.
- [ ] Сбор/прибыль/выплата соответствуют действующим формулам; пример 169.30 TON не становится универсальным правилом.
