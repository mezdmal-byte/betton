## Общая логика
Одна компактная форма: тип события → вопрос и два исхода → условия и применимые сроки → проверка и редактирование → сценарное завершение. Не возвращать старые восемь шагов, не создавать три полностью независимые формы. Сумма и коэффициент задаются в заявках, не в создании события. Валидировать поля на текущем шаге.

### Публичное
- Категории на старте: футбол, киберспорт, теннис, баскетбол, хоккей, MMA/единоборства, политика, **Другое**; список расширяем.
- Правила/описание, критерии **каждого исхода**, способ определения результата, действие при неопределимости, **обязательный основной источник** и **необязательный дополнительный/резервный источник** (название и ссылка).
- **Новое решение пользователя:** убрать с публичной формы `Приём ставок до` и `Предполагаемое завершение` (заменяет прежние требования). До внедрения выяснить, как сервер/модерация получают необходимые даты; самовольно не возвращать поля в макет.
- Проверка → **Отправить на модерацию** → подтверждение **Заявка отправлена на модерацию**. Не показывать «опубликовано».

### Частное без гаранта
- Вопрос/2 исхода → правила и порядок решения создателем → сроки → проверка → создать → пригласить участников по ссылке.
- Нет обязательной категории и внешнего источника. **Предполагаемое завершение** оставить. Поле `Приём ставок до` ранее присутствовало, актуальное решение требует уточнения; пользователь явно отменил его только для публичного.
- Отдельный обязательный шаг `Краткое описание` не возвращать.
- Подтверждение: **Частное событие создано**; CTA **Пригласить участников**.

### Частное с гарантом
- Вопрос/2 исхода → условия и сроки (предполагаемое завершение сохранить) → проверка → **существующий** `GUARANTOR-PICK-01` → приглашение гаранта → согласование в существующем `GUARANTOR-01` и вкладках `Чат / Условия / История`.
- Выбор гаранта **не означает согласие**; оба участника должны явно подтвердить актуальную редакцию. Системный срок решения гаранта — 24 часа после окончания события. Активация гарантийного механизма требует предусмотренных условий обеспечения.
- **Противоречие двух генераций:** после выбора не показывать зелёное «Событие создано и готово». Правильное промежуточное подтверждение: **Приглашение гаранту отправлено / Ожидаем ответ** с CTA **Перейти к согласованию**.

## Единая логика финальных состояний
