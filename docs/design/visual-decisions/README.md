# BetTON — визуальные решения и правки к макетам

**Статус:** рабочий реестр договорённостей для будущего переноса в Figma.  
**Дата:** 2026-10-27  
**База продукта:** PR #24 (`3907441`). Не использовать PR #25 Exchange/Folio/Pocket как принятый стиль.  
**Принцип:** изображение — композиционный ориентир, согласованные продуктовые правила и тексты — из существующего BetTON/backend. Никакие PNG не являются готовыми API/UI-спецификациями.

## Правила работы с референсами

1. Один PNG = один экран/состояние. Не регенерировать три экрана в одном изображении.
2. Принятую композицию **не перерисовывать целиком** ради двух мелких правок. Сохранять исходник, записывать корректировки в этом реестре, исправлять при переносе в Figma.
3. Одобренная основа ≠ пиксельный финал. Перенос: Figma components → согласованный copy/API → React → visual regression.
4. Отдельный экран и состояние на каждый существенный пользовательский путь. Дизайн должен работать и без картинки события.
5. Стиль: очень светлый серый фон, белые карточки, спокойный графит, оранжевый как акцент; обязательная будущая dark theme. Компактно, понятно, с аккуратной типографикой и единой сеткой.
6. Валюта **TON**, а не рубли. Коэффициенты единообразно с двумя знаками. Нельзя выдумывать ставки, графики, статусы, расчёты или работоспособность функций.
7. У каждой записи: исходная картинка, оценка, **что оставить**, **что исправить в Figma**, состояние.
8. Эскизы и изменения не затрагивают production, main, PR #25, PR #28 или API без отдельного решения.

## Общие решения

### Навигация
- Нижняя панель **пять разделов**: Главная / Мои ставки / **Создать** (центральный акцент) / Уведомления / Профиль. Не добавлять Live/«Сейчас» при первом выпуске.
- Избранное добавляется звёздочкой **на карточке**, доступно из левого бокового меню; не отдельный шестой пункт нижней панели.
- Слева меню: профиль и баланс, категории, избранное, мои события, черновики, история, как это работает, правила/безопасность, поддержка, настройки, тема, язык. Каждый пункт должен вести к существующему экрану либо быть явно помечен как планируемый.
- Верх главной: фирменная надпись BetTON, текстовые вкладки **Все / Киберспорт / Спорт** (активная с оранжевым подчёркиванием), кнопка «Все категории», отдельная строка **сортировка / фильтры**; не использовать массивные квадратные серые кнопки.
- «Популярные»/огонь — только по честному, явно определённому показателю активности; без случайных меток.

### FEED-01 — Главная лента
**Сохраняем:** светло-серую подложку и белые плотные карточки, название/этап/срок, два исхода с коэффициентами, три показателя, избранное-звёздочку, центральное «Создать» в нижней навигации.  
**Правки Figma:** не копировать придуманную ставку рублями; единый формат коэффициентов; условия «с фотокарточкой / без»; корректные интерактивные карточки, фильтры, сортировка и пустые состояния; реальные данные с backend.

### EVENT-01 — Страница события (главный подробный экран)
**Основной ориентир** — `event-layout-v1.png` с графиком/показателями/предложениями/правилами/сделками/обсуждением/фиксированной ставкой. Двухчастное изображение отражает **одну длинную страницу**, не два разных экрана.
**Меняем только:**
1. **Шапку** — компактная карточка `event-header-v1.png`: текст слева, эмблемы исходов справа; не гигантский тематический фотобаннер. Варианты с дополнительным изображением и без него. Загрузка фото создателем и добавление модератором — **отдельная функция, сейчас не подтверждена в API**; не реализовывать фиктивно. Статус/публичность в стандартизированном месте.
2. **Предложения участников** — это компактный **стакан**, а не обобщённые «лучшие». Показать по умолчанию около 3 ценовых уровней на исход, фильтр **Все / исход A / исход B**, «Показать все». Для каждого уровня **Коэффициент** и **Доступно (TON)**; убрать «Всего» и суммы исторически выставленного. Не приписывать агрегированному уровню конкретного участника.
**Ни в коем случае не переносить из `event-rejected-regeneration.png`** двухколоночное сжатие правил, последних сделок, обсуждения или действий.
**График:** **две линии исходов одновременно** по реальным исполненным P2P-сделкам, единая ось времени, касание показывает исход/коэффициент/время/размер исполненной сделки; опционально «Показать суммы сделок» со столбиками. Не подменять кривыми вымышленных данных. Не заставлять выбирать исход ради просмотра его линии.
**Метрики:** «В предложениях» — деньги в открытых заявках (не путать с исполнимой конкретным зрителем ликвидностью); «Предложений» — достоверное количество заявок, только если backend его предоставляет; «Заключено ставок» — объём исполненных ставок, не «оборот».
**Правила:** краткое «Как определяется результат» + реальный основной/резервный источник, разворачиваемые критерии каждого исхода и другие подробности; не выдумывать универсальный HLTV для Dota 2.
**Обсуждение:** компактный встроенный превью-блок с переходом в существующий чат; не смешивать с закрытым чатом гаранта.
**Торговля:** два исхода, «Быстрая ставка» и «Свой коэффициент» без дублирующей кнопки «Ваш коэффициент». Закреплённая панель выбора исхода и суммы. При расчёте — только backend order quote, учитывать несколько уровней и частичные исполнения.

### GUARANTOR-01 — Гарант
Сохраняем карточку гаранта, объяснение его роли, сроки и «Что будет дальше».
Пересобрать **центральное согласование**: настоящий чат создателя и гаранта; системные карточки изменений условий с ревизией; отдельная карточка вознаграждения и встречных предложений (фикс / процент / фикс+процент / процент с минимумом); подтверждение конкретной актуальной редакции. Разговор в чате **не является автоматическим подтверждением финансово значимого соглашения**. Другой участник принимает утверждённые правила отдельно. Показывать реальные этапы `invited/review/collecting/active/settled/cancelled` и права по ролям. Не писать, что гарант «участвует в ставке». Вознаграждение берётся из прибыли победителей по серверным правилам, 24 ч на решение после окончания события.

### MY-BETS-01 — «Мои ставки»
**Решение:** исходная композиция уже подходит; **не перегенерировать** ради правок верхней части.
**Три верхние карточки:**
- **В ставках — N TON:** исполненные позиции, результат которых ещё не определён.
- **В предложениях — N TON:** деньги в открытых неисполненных остатках заявок, включая остатки частично исполненных.
- **Завершено — N пари:** количество закрытых участий (победа, поражение, отмена/возврат), **не** сумма исключительно выигрышей или «Выплачено TON».
Не складывать показатели одного и того же частичного исполнения дважды.
**Вкладки:** **Все / В ставках / Мои предложения / Завершённые**. «С гарантами» — фильтр, не отдельная первичная вкладка.
Карточки с частичным исполнением показывают отдельно «Исполнено», «Осталось в предложении» и возможность отменить **только неисполненный остаток** по правилам.
Прибыль, выплаты и возвраты — честные серверные величины, без выдуманных начислений.

## Что осталось для следующей генерации
- Выбор гаранта (перед приглашением).
- Разговор/согласование с гарантом как отдельное подробное состояние.
- Создание события (важные шаги, не изобретать новую финансовую логику).
- Уведомления, профиль, дополнительные состояния.
- Затем адаптация пяти экранов первого знакомства, анимации, тёмная тема.

**Критерий перехода к Figma:** картинка нравится по композиции и основной иерархии; все расхождения, ограничения и непоказанные состояния записаны здесь. Пиксельная точность и реальные тексты — этап Figma/React, не бесконечная генерация.
