## Воспроизводимая визуальная проверка

Workflow `.github/workflows/visual-v1-app.yml` устанавливает Chromium в GitHub Actions, снимает **настоящий `/v2/` App** из React entrypoint, включая viewport-обёртку, затем выполняет существующие fixture-проверки EVENT/legacy и workflow гаранта. Доступ к заблокированному cloud preview не обходился.

Скрипт `frontend/scripts/capture-app-v1.mjs` поднимает Vite; реальные API и Telegram SDK не вызываются. Playwright перехватывает запросы и подставляет детерминированные данные. Неизвестные внешние запросы и непредусмотренные записи блокируются. Разрешённые synthetic POST — только mock auth и heartbeat; они также обслуживаются перехватчиком без backend.

Матрица: **320/360/390/430 × 550/600/700/844**. На каждой точке — четыре экрана, три страницы деталей, лента и drawer. Дополнительно снимаются нижняя часть коротких деталей/онбординга, прокрученные лента и меню, модель клавиатуры, fullscreen success/denied, вкладки настоящего события. Проверяются Telegram Back, Escape, удержание фокуса drawer, возврат фокуса деталей, модель touch-свайпа, safe area и отсутствие перекрытия прокрутки нижней панелью.

Финальный [Chromium workflow](https://github.com/mezdmal-byte/betton/actions/runs/41391162691) успешен на коде `bc5b9f85ad1e33c96a4c1afcbd817882829544d3`: 221 App-снимок до и 221 после, after errors=[]; ещё 87 visual/legacy и 25 workflow-снимков. Frontend: 209 tests + build; browser recovery: 6 + 74; SQLite: 496 passed / 14 skipped; PostgreSQL: 522 passed. Подробности — [design-qa.md](../../design-qa.md). Полный артефакт Actions хранится 14 дней; выбранные PNG и [матрица измерений](visual-v1-qa-20261102/app-matrix.json) закреплены в репозитории.

## EVENT и гарант

После визуального подтверждения первых блоков расширены проверки: четыре вкладки настоящего события на 320/390 × 600/844, включая прокрутку и fullscreen. Пустая история сделок показана честно, без выдуманного графика. Из UI EVENT изменена только высота шапки.

Изолированные workflow-проверки гаранта покрывают приглашение, согласование, активное событие, выбор другого гаранта; блокировку устаревшей редакции; явное подтверждение решения; сохранение обоснования при отказе сервера; возврат с отказа от приглашения и единственный финальный mock-запрос; отмену с отдельным подтверждением и номером редакции. Эти проверки не являются settlement-тестом и не выполняют финансовых операций.
