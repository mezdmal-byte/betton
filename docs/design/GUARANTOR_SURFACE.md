# Guarantor surface — Operate

User-confirmed scope: add private-event guarantor workflow to the existing Figma
implementation, preserve its design. No new visual identity or concept exploration.
Audience: ordinary Telegram users, not professional traders. The priority is to
understand who checks the result, what was agreed, and whether betting is open.

## Direction contract

THESIS: make the named verifier and the agreed version visible before a user risks
their balance. Review and acceptance are explicit actions, not chat implications.

OWN-WORLD: inherit incumbent porcelain/cobalt tokens, existing Button, bottom
navigation, system typography, input borders, light/dark semantics. No new assets.

STORY: creator selects an available person; guarantor reviews; creator clarifies;
both confirm; bettors read the frozen terms. Later the verifier supplies evidence.

FIRST VIEWPORT: existing market question/header, then verification state, guarantor
identity, deadline and terms. During review the next action is accept or clarify;
active bettors see consent before placing an order. Profile links to guarantors,
whose page puts own readiness and invitations before the general directory.

FORM: local extension of the established interface, not a new visual world. No
concept-seed or generated comp: the user explicitly asked to keep the current UI.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish
review, the verdict, DESIGN.md, and every shipping raster carrying its provenance.
For this extension DESIGN.md is retained, not rewritten. Its earlier exploration
wording is stale; current user instruction and actual Figma-branch tokens govern.

Evidence: `.impeccable/review/review-mobile.png`, `active-mobile.png`,
`directory-desktop.png`, `directory-small.png`. Captures use test-only identities
and an isolated API database. They do not claim a Telegram-hosted device test.
