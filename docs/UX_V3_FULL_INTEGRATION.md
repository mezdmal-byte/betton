# BetTON UX v3 — тестовая интеграция

Рабочая ветка: [feature/ux-v3-full-integration](https://github.com/mezdmal-byte/betton/tree/feature/ux-v3-full-integration).
Техническая основа: `feature/figma-full-implementation`, commit `330d791`.
Версия от 23 октября 2026 года. Это промежуточная тестовая интеграция, **не утверждённый релиз**.
Admin Center не входит в эту работу.

## Запуск на Windows

1. Установить Python 3.11+ (с командой `py`) и Node.js LTS.
2. Скачать рабочую ветку и запустить **`start-ux-v3-local.bat`** из её корня.
3. После сборки открыть `http://127.0.0.1:8877/sandbox/?actor=creator`.
4. Для смены роли использовать `actor=participant`, `actor=guarantor`, `actor=moderator`.
   Удобно открыть роли в разных окнах браузера. Хранилище настроек на одном origin общее;
   черновики создания разделены по пользователю.
5. Завершить сервер через Ctrl+C. Существующие BAT-файлы проекта не менялись.

Установщик создаёт `.ux-preview/windows-venv`, устанавливает requirements и собирает frontend.
Панель работает **только на этом компьютере**, не публикуется в интернет.
Сам BAT не запускался на настоящей Windows: Python-сервер, изоляция и API проверены на Linux.
На телефоне и внутри настоящего Telegram эта итерация ещё не проверена.

Альтернатива после установки зависимостей и `cd frontend && npm ci && npm run build`:

```bash
python scripts/ux_v3_preview.py
```

Сервер не загружает production `.env`, не подключает бот/webhook и настоящие кошельки.
Использует собственную маркированную `.ux-preview/betton-test.sqlite` и отказывается открывать
постороннюю немаркированную базу. Вход проверяет обычную Telegram HMAC-подпись, сформированную
локальным тестовым токеном; штатная авторизация приложения не отключается.
Host, Origin и адрес клиента ограничены loopback. CSP запрещает обращения к внешнему API.

Тестовые записи создаются **только в этой изолированной базе**. В исходной или рабочей базе
записи не создавались. Доступность гаранта подчиняется существующему heartbeat: для позднего
выбора гаранта откройте его роль и включите доступность.

## Состав реализации

| Раздел | Реализовано | Проверка / ограничение |
|---|---|---|
| Знакомство | Пять иллюстрированных экранов; три подробных описания; пропуск; повторное открытие из помощи | Исходные SVG экспортированы из Figma; иллюстративный холст 350×391. Браузерная сверка ещё не выполнена |
| Главная | События, поиск, фильтры, реальные исходы; сумма активных неисполненных собственных средств | `/feed/stats`, точная строка nanoTON; тест частичного исполнения; нет подстановки 1250 TON |
| Событие / предложения | Детали, предложения участников, отдельные уже исполненные ставки, реальные коэффициенты | Существующие API; расчёты matching не заменены |
| Размещение ставки | Быстрое исполнение, свой коэффициент, подтверждение/результат, частичное исполнение | Выплата и средний коэффициент берутся из server preview, не из запрошенного коэффициента |
| Мои ставки | Активные / Мои предложения / Завершённые; вторичные баланс, доход, история | Реальные API; выбранный подраздел сохраняется между переходами |
| Создание | Три шага + проверка, три ветки, ошибки на текущем шаге, черновик на пользователя | Реальный `/ux-v3/events`; старый восьмишаговый компонент не подключён к основному маршруту |
| Гарант | Список со ссылкой «Профиль», отзывы/рейтинг/статистика, приглашение, полноценный чат, редакции правил, переговоры | Реальные действия и права. Публичная поэлементная история проверок профиля пока не добавлена |
| Результат гаранта | Только назначенный одобренный гарант; 24 часа от конца события; без пересмотра; возврат при пропуске срока | Новые события v3; legacy-события сохраняют старый протокол |
| Вознаграждение гаранта | Предложение/принятие суммы, процента от чистой прибыли или их сочетания | **Финансирование, резервирование и выплата не подключены; платное событие не открывается** |
| Частное без гаранта | Условия и согласие до первой ставки, результат/невозможность определить результат от создателя | Использует существующие settle/void; повторные и чужие действия защищены |
| Модерация | Очередь, все поля, источники, отдельные сроки, сравнение/оригинал, отклонение, публикация оригинала | Изменённая редакция сохраняется, но публикация блокируется до решения о согласии автора |
| Профиль / настройки / история | Существующие реальные API и навигация сохранены; баланс и обновлённая терминология | Новые формы/онбординг RU/EN/ZH; некоторые старые профили/модерация/чат ещё имеют русские строки |
| Уведомления | Колокольчик, реальный unread, получение списка, подтверждение прочтения, переход к событию | GET/POST сервера, без фиктивных уведомлений |
| Lobby / обсуждение | Существующие API и связанные переходы сохранены | End-to-end проверка в настоящем Telegram не выполнена |
| Навигация | Стеки вкладок, фильтры, восстановление прокрутки после загрузки, Back с единственным активным владельцем | Автотест вложенного Back; реальный host и жесты требуют проверки |
| Темы / адаптивность | Dark A / Light C, существующие токены, скроллируемые формы, ограничение desktop-контента 560 px | Фактические 360/390/430 и desktop screenshots **пока не сняты** |
| Кошелёк | Существующий экран с явно недоступными операциями | Настоящие TON-пополнения/выплаты не подключались |

Основные сценарии:

- Публичное: тип → вопрос/исходы/категория → правила/критерии/источники/сроки → проверка → модерация.
- Частное без гаранта: тип → вопрос/исходы → правила/способ результата/сроки → проверка → ссылка → согласие участника → ставки.
- Частное с гарантом: тип → вопрос/исходы → правила/сроки → проверка → список/профиль гаранта → приглашение → чат/редакции/вознаграждение → подтверждение → открытие (если нет неподдерживаемой оплаты).

## Технические изменения и проверки

Добавлены companion-таблицы `EventConfigV3` и `EventRevisionV3`; старые события не преобразуются.
При работе с обычным backend `ensure_schema` создаст эти таблицы в выбранной БД; не запускать
данную ветку на production-конфигурации. Для проверки использовать только отдельный sandbox.
Frontend не придумывает успешную модерацию, выплату, открытие или исполнение при ошибке сервера.
Авторизация, сопоставление P2P и существующий денежный алгоритм остаются серверными.
Автоматическая отмена и решение создателя переиспользуют существующую транзакционную логику;
добавлены проверки полномочий и версия протокола. Независимая AST-проверка подтвердила
неизменность ядра денежных проводок void.

Проверки последней итерации (точные команды):

| Команда | Результат |
|---|---|
| `.ux-preview/venv/bin/python -m pytest -q tests` | 289 passed, 12 skipped; SQLite; 12 PostgreSQL journal tests требуют отдельной BETTON_TEST_DATABASE_URL |
| `cd frontend && npm test` | 135 passed в 25 файлах; включены `.test.tsx`, ранее общий шаблон их пропускал |
| `cd frontend && npm run build` | TypeScript + Vite проходят; остаётся предупреждение о размере основного JS >500 kB |
| `git diff --check` | Проходит |
| Локальный сервер + HTTP | HTML, подписанная авторизация, реальный seed/feed, запрет чужого Host/Origin проверены |
| Windows / настоящий Telegram / phone / visual E2E | Не проверены; не выдаются за успешные |

Охвачены: поля публичного события, одинаковые исходы/пустой источник, доступ к частным условиям,
согласие до ставки, права создателя, сохранение автора при модерации, устаревшие редакции,
неподдерживаемая оплата, приватность переговоров, своевременное решение, запрет пересмотра,
отозванный статус гаранта, замена гаранта со сбросом соглашений, таймаут/идемпотентность,
rollback при неверном банке, повторные параллельные возвраты, отменённое частное событие без утечки ссылки.

В тестовом seed: собственное предложение 100 TON, исполнено 40, отдельное предложение 50 →
110 TON в активных предложениях. Это реальные записи **локальной тестовой БД**, не данные платформы.
Имена и суммы онбординга — явно учебные иллюстрации. Основные connected-экраны получают данные API;
fixtures остаются только в изолированных компонентах/Storybook и не подменяют API-ошибку.
