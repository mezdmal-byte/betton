# BetTON Admin Center — локальный просмотр тестовых данных

Отдельное приложение для компьютера. Не запускает `app.main`, Telegram-бота, Mini App, миграции, matching, обработку истечения заявок или settlement. Основной BetTON продолжает работать независимо.

## Возможности

| Раздел | Подключённые данные |
|---|---|
| Обзор | Число пользователей/событий и остатки открытых предложений по сохранённым статусам БД |
| Пользователи | Поиск по внутреннему ID, Telegram ID, логину и имени Telegram; карточка с заявками, созданными событиями, исполнениями и журналом |
| События | Поиск по ID/названию; создатель, исходы, состояние, банк исполненных ставок, заявки, исполнения, журнал, сохранённые результаты и условия гаранта, когда его модуль присутствует |
| Предложения | Поиск заявки по ID; фильтры пользователя/события; исходная сумма, исполненная часть, оставшийся резерв, возврат; карточка заявки |
| Исполнения | Фильтры пользователя/события/заявки; карточка, оба участника и их заявки |
| Денежный журнал | Фильтры пользователя/события/заявки/исполнения; карточка движения, направление и связанные объекты |
| Результаты расчёта | Только сохранённые строки `settlement_records`, без запуска расчёта |

ID связанных пользователей, событий, заявок, исполнений и записей журнала — ссылки. Работают Back браузера и прямые ссылки с `#`; поиск и фильтры сохраняются в адресе. Длинные списки разбиты на страницы по 30 строк; API ограничен 100 строками на запрос. В карточках показываются явно обозначенные ограниченные выборки и ссылки на полные списки.

### Финансовые значения

- `balance_nano` — доступные средства; не включает резерв заявок или банк исполненных ставок.
- Остаток резерва — `remaining`; исполнено — `filled`; возвращено — `refunded`.
- Обзор суммирует `remaining` только заявок со статусом `open` в событиях со статусом `open`. Это снимок **сохранённых статусов**, а не проверка актуальности времени события. Просмотр не выполняет закрытие просроченных событий/возвраты. Уже исполненные ставки, потенциальная выплата и встречный будущий объём сюда не включаются.
- Целые nanoTON передаются строками и форматируются через `BigInt`, без потери точности JavaScript.
- Денежные поля `settlement_records` в существующей модели — legacy float в TON. Они подписаны отдельно и не пересчитываются панелью.
- Пометка охвата журнала `full` означает сохранённый признак покрытия; это **не** результат автоматической сверки. Для старых событий полная история может отсутствовать.

## Запуск Windows — рекомендуемый способ

Нужны Git, Python 3.11+ с Windows Python Launcher (`py`) и **существующий локальный файл тестовой SQLite-базы** совместимой версии BetTON. Предпочтительно использовать отдельную согласованную копию тестовой базы. Не копируйте произвольно работающий SQLite-файл в WAL-режиме: получите согласованный снимок стандартными средствами SQLite.

1. Скачайте ветку с кодом:

```bat
git clone --branch feature/admin-center-readonly-v1 --single-branch https://github.com/mezdmal-byte/betton.git
cd betton
```

2. Запустите `setup-admin-center.bat`. Он создаст отдельное окружение `.venv-admin`, установит только зависимости панели и запросит путь к существующей **тестовой** SQLite-базе, отдельный логин и новый пароль (минимум 16 символов). Пароль вводится скрыто, сохраняется только PBKDF2-хеш. Схема проверяется чтением; отсутствующая база не создаётся.
3. Запустите `start-admin-center.bat`.
4. Откройте **http://127.0.0.1:8765** и введите созданные логин/пароль в запросе браузера. Остановка — `Ctrl+C` в окне сервера.

Настройки сохраняются только локально в `.admin-center.json`, исключённом из Git. Не пересылайте этот файл. В нём есть путь к БД и хеш пароля. Это не Telegram-авторизация. При смене администратора повторите настройку. HTTP Basic может кешироваться браузером: для завершения локального сеанса закройте отдельный профиль/все его окна браузера и остановите сервер.

Проверка подключения без запуска веб-сервера:

```bat
.venv-admin\Scripts\python.exe -m admin_center.launcher --check
```

BAT-файлы подготовлены для Windows; выполнение проверено на Linux через тот же Python entry point. Нативный запуск Windows в этой среде не проверялся.

## Явная настройка через окружение

Альтернатива мастеру. Установите зависимости в отдельное Python-окружение, получите хеш командой `python -m admin_center.security` и задайте все четыре переменные **в одном окне CMD**:

```bat
set "BETTON_ADMIN_ENVIRONMENT=test"
set "BETTON_ADMIN_DATABASE_URL=sqlite:///C:/betton-data/betton-test.db"
set "BETTON_ADMIN_USERNAME=owner"
set "BETTON_ADMIN_PASSWORD_HASH=ВАШ_ПОЛНЫЙ_ХЕШ_ИЗ_КОМАНДЫ"
python -m admin_center.launcher --check
python -m admin_center.launcher
```

Переменные `DATABASE_URL`, `.env` основного приложения и секреты Render не читаются. Если задана хотя бы одна из четырёх переменных панели, конфигурация целиком берётся из окружения, без смешивания с сохранённым файлом. Маркер `test` — явное указание оператора, а не автоматическое доказательство происхождения SQLite-файла.

Для PostgreSQL адаптер принимает только `localhost`, `127.0.0.1`, `::1`, имя БД с `test`/`sandbox`, без query-параметров URL. Нужен отдельный SELECT-only пользователь: не владелец таблиц, не superuser, без CREATEDB/CREATEROLE и прав записи. Используются read-only транзакции, тайм-аут SQL 5 секунд и проверка роли. Рабочую/удалённую БД подключать нельзя. PostgreSQL-подключение **не проверено на настоящем сервере в этой среде**.

## Защита и границы

- Сервер запускается только на `127.0.0.1:8765`, одним процессом, без доверия proxy headers. Не добавляйте туннели или публичное размещение.
- Каждый API-маршрут и статический ресурс защищён серверной авторизацией. Нелокальный socket peer, proxy headers, сторонний Host и cross-site запросы отклоняются. После 10 неудачных попыток вход блокируется на 10 минут в рамках процесса.
- Есть только GET-маршруты. POST/PUT/PATCH/DELETE и другие методы изменения сервер отклоняет независимо от пути.
- SQLite открывается `mode=ro` + `PRAGMA query_only=ON`. Дополнительный SQL-guard разрешает только чтение/интроспекцию. Никаких `create_all`, миграций или записей при запуске.
- Модерация, изменение баланса, возвраты, отмена заявок и выплаты недоступны. Внешних TON-кошельков и ключей нет.
- Приватные share-токены событий не экспортируются; список колонок задан явно. Ответы с данными не кешируются; действуют CSP и запрет встраивания.
- Это одна локальная читающая роль. MFA, удалённый вход, несколько администраторов и неизменяемый аудит доступа в эту версию не входят.

## Проверки

Для тестов установите зависимости существующего проекта (`requirements.txt`); они используют отдельную временную БД из `tests/conftest.py`. Не задавайте URL рабочей базы для тестов.

```bat
python -m pytest -q tests/test_admin_center.py tests/test_admin_center_integration.py tests/test_p2p_journal.py tests/test_integer_money.py
node --check admin_center/static/app.js
```

Результат проверки 2026-10-23: **48 passed**. Покрыты авторизация всех читающих маршрутов/ресурсов, ограничения Host/peer/proxy, перебор паролей, запрет операций, native SQLite read-only, неизменность файла после чтения, поиск/пагинация/границы ID, точность nanoTON, отсутствие импорта рабочего приложения и чтение данных, созданных существующим P2P-сервисом в изолированной БД. Дополнительно проверены существующие тесты журнала и integer-money. Есть предупреждения о deprecated API зависимостей; проваленных тестов нет.

Опциональная проверка реальным Chromium:

```bat
python -m pip install playwright
python -m playwright install chromium
python tests/admin_center_browser.py
```

Она запускает панель с временной синтетической БД на свободном порту 8765, проходит поиск и связанные карточки, Back, состояния ошибки/неподключённого источника и ширины 1440/1024/390. Проверяет отсутствие запросов записи и внешних запросов. В текущей среде — PASS (Chromium 134, Playwright 1.51).

## Что ещё не подключено

Полная автоматическая сверка P2P, audit/error logs, инциденты и трассировки, метрики backend/бота, мониторинг резервных копий, оповещения, управление ролями, блокчейн. В этих разделах явно указано отсутствие данных. Все 15 Figma-экранов не объявляются полностью реализованными.

**База пользователя пока не подключена:** готового файла/параметров существующей тестовой базы среди доступных материалов не найдено. Проверки выше выполнены на изолированных данных. После предоставления локального тестового файла выполните мастер и `--check`; не используйте production.
