# BetTON UI quality

Read `docs/BETTON_BIBLE.md`, `PRODUCT.md`, `DESIGN.md` and
`docs/design/DESIGN_PIPELINE.md`. React/TypeScript/Vite/CSS Modules are the existing stack;
money, matching, access and settlement remain backend contracts.

For design work read `.cursor/skills/impeccable/SKILL.md`, run its Windows context command once,
and load its relevant playbook/craft floor. Use `prototype` for explicitly requested divergence;
one surface, full-size interactive alternatives, exact picker, no replacement of production UI
before the human chooses. Use `emil-design-eng` for interaction/reduced-motion craft.

Verify actual screenshots at 320/360/390/430px, light/dark and RU/EN/ZH when affected. Check press,
focus, disabled/loading/error states, overlay hit targets, keyboard access and Back cleanup.
No fake liquidity, chart fills, or client-side monetary estimates replacing server quotes.

Run `cd frontend; npm test; npm run build` and relevant Playwright tests. Use one screenshot-based
critique, a batched correction and at most one confirmation pass. A Figma comparison requires an
approved frame and exact measurements; a text review alone is not visual QA.
