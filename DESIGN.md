# BetTON design context adapter

This is a design-skill adapter, not an approved design system.

## Current status

- **No visual direction is approved.**
- The current React styling is implementation scaffolding.
- The 2026-09-22 Figma exploration named Tape / Issue / Instrument was rejected as a visual direction. Keep it only as research history and an anti-reference.
- Do not extrapolate those frames into more screens.

## Product design register

BetTON key screens are **Operate** surfaces: users scan markets, understand price/liquidity, and execute trades. Expression matters, but it must not reduce clarity, trust, speed, or the visibility of real P2P states.

## Desired qualities

- distinctive enough to feel authored rather than template-generated;
- financially credible without becoming a pro trading terminal;
- mobile-first and natural inside Telegram;
- clear hierarchy between question, probability/price, liquidity, criteria and action;
- interaction craft that feels responsive and deliberate;
- visual restraint without becoming sterile.

## Reject by default

- generic AI SaaS styling;
- repeated rounded cards as the entire layout;
- teal/green decoration everywhere;
- sportsbook/casino chrome;
- neon Web3;
- fake charts, fake liquidity or decorative market data;
- excessive pills/badges;
- copied reference screens;
- design judged only from text descriptions or tiny side-by-side mockups.

## Current exploration target

Work on **one 390px Markets Feed surface first**. Build full-size live variants in an isolated prototype harness. Do not move to Market Detail or Trade until the user chooses a Feed direction.

Reference and iteration process is defined in `docs/design/DESIGN_PIPELINE.md`.

When a direction is chosen, this file should be replaced with the actual approved visual world: typography, surfaces, spacing, color semantics, motion, navigation and component principles.
